Design review
-------------
1. Coverage is by module origin, not public names or textual name prefixes.
   env.constants.fold includes non-public constants; getModuleIdxFor? selects
   declarations actually supplied by the imported module. Private declarations
   are not omitted because their expanded names differ from public names.

2. scripts/verify_sources.py checks that every tracked Lean proof source is an
   explicit library root and that AllDeclarationsAudit.lean explicitly imports
   every root. It also checks the roots' build/default-target configuration.
   The checker alone selects its direct imports; source coverage is therefore
   a necessary companion gate. The combined verify.py pipeline runs that gate,
   builds, runs the whole-declaration checker, and rechecks source coverage.

3. CollectAxioms traverses declaration types and values, including opaque
   values, and constructor/recursor/inductive dependencies. The shared visited
   set is a performance improvement without a coverage loss: the environment
   is fixed during the traversal, and every target is visited or was already
   traversed as a dependency. An unused custom axiom is itself a target and
   cannot hide merely because no public theorem uses it.

4. The traversal uses env.checked, as Lean's own CollectAxioms implementation
   specifies. Thus dependency collection follows checked kernel declarations
   rather than an elaborator's potentially incomplete transient declaration.
   These targets come from completed imported modules.

5. Only propext, Classical.choice, and Quot.sound are allowed. There is no
   wildcard for generated names, private names, or external dependencies.
   sorryAx and an arbitrary custom axiom are rejected.

Unsafe root filtering
---------------------
The first unfiltered version included unsafe compiler implementations among
audit roots. Isolated interpolated-string examples caused it to encounter
lcProof, which Lean's compiler uses while erasing proofs in unsafe generated
code. The full repository check independently encountered a generated
specialization represented as an unsafe axiom.

Restricting ROOTS to !ConstantInfo.isUnsafe is principled. Theorems always
have isUnsafe=false; safe definitions and their generated safe declarations
remain selected. Lean's safety classification, rather than a brittle generated
name convention, determines the exclusion. The separate lexical gate rejects
user-written unsafe and partial declaration syntax.

Crucially, the current checker does NOT filter CollectAxioms dependencies.
Any unexpected axiom encountered transitively from a selected safe declaration
still fails. The whitelist was not enlarged to include compiler internals.
Tests below verify that the root filter does not conceal interpolated sorry.

The initial automatically imported Init module produced a harmless zero-count
line; the current implementation explicitly removes it from the module list,
so reported module counts correspond to the selected project modules.
