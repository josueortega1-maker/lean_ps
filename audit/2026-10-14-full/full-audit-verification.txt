   actual dependency trees against lake-manifest.json. Added

   every manifest package must be a full-commit-pinned Git checkout at exactly

   generated cache files remain allowed. The parent integrated checks before
   and after the proof run. The actual environment passes: Lean 4.19.0 and all
   nine pinned clean checkouts. Six new tests cover mismatches and dirty/missing
   dependency trees.

2. Declared Lake roots alone do not guarantee a default library build checks
   them. Reproduced with a real two-root temporary Lean project: roots Main and
   Unbuilt, globs Main; Unbuilt contained an invalid proof, yet lake build exited
   zero. The previous source guard accepted it. verify_sources.py now rejects
   globs differing from the explicit roots and nondefault defaultFacets. Tests
   cover both omissions. Existing defaultTargets coverage remains enforced.

3. A lexical source scan is not a parser or a complete proof-dependency audit.
   Reproduced a missed placeholder inside executable string interpolation:
     def unchecked : String := s!"{(show Nat from sorry)}"
   Comments/strings are blanked, so this source is invisible to the lexical
   token rule. Expanding that Python scanner into a Lean parser would be fragile.
   The parent implemented AllDeclarationsAudit.lean to traverse dependencies of
   every constant originating in every project root, including private helpers,
   definitions and generated declarations. This closes the selected-public-
   declaration coverage gap using Lean's own environment. My guard requires
   every root to have an explicit import in that audit. Its CLI now calls the
   lexical scan a token check rather than claiming complete placeholder absence.
   The parent owns compilation and full execution of the new Lean audit.

4. New untracked Lean files created during verification were not covered by
   the final tracked-file hash comparison. Changes to .gitignore were also not
   hashed, although they alter the source guard's view of untracked files.
   The parent added .gitignore to the inputs and final source/environment
   rechecks. Regression tests verify each final guard can fail a previously
   successful build, and that .gitignore affects the source hashes.

5. A rerun abruptly terminated before finally could retain an old success:true
   receipt while replacing some logs. The runner now atomically installs a new
   success:false receipt before metadata or subprocesses and atomically replaces
   it at completion. A real child-process regression calls os._exit, bypassing
   finally, and confirms the previous success cannot survive. The existing
   missing-tracked-source failure test remains passing.

generated cache artifacts, as ordinary Lean verification does. The new checks
bind the declared toolchain version and dependency source trees; they do not
claim independent binary reproducibility or adversarial attestation. The local
runtime uses the documented, external own-process readlink compatibility shim;
the Lean kernel and project proofs are unchanged by it.

new all-project gate: it checks expected names/output completeness and the
